# Vigil MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the tkinter prototype with a PySide6 surveillance app whose display never waits on inference, with dlib face recognition, motion gating, a reviewable event log, and a person gallery.

**Architecture:** One process, threads per camera plus one inference thread, one DB writer, one notifier. Capture publishes every frame to a one-slot display queue, every second frame to motion, and time-sampled frames to a bounded inference queue. The inference thread owns tracking and recognition and emits events to a bus. The GUI timer only reads the latest frame and a TTL overlay store.

**Tech Stack:** Python 3.9+ source compatible, 3.12 release target, PySide6, OpenCV, dlib 20, NumPy, Pydantic 2, SQLAlchemy 2 Core, SQLite WAL, TOML (tomllib/tomli/tomlkit), PyInstaller.

**Spec:** `docs/superpowers/specs/2026-11-11-vigil-mvp-design.md`

## Global Constraints

- No em dash character in any written text. Use comma, period, colon, or parentheses.
- Source must run on CPython 3.9.23 and 3.12.x. No `match`, no `X | Y` annotations evaluated at runtime.
- `LatestFrame` capacity is 1 and `put` never blocks.
- Inference queue capacity is 4 and overflow drops the oldest item.
- No module on the display path imports dlib.
- SQLite runs in WAL mode with foreign keys on, one writer thread.
- The developer log never contains camera URLs with credentials, embeddings, or image bytes.
- Every threshold and fps value is configurable.
- All UI text is sentence case, no tracked uppercase labels, no em dashes.
- Tests run with `pytest -q` and need neither a camera nor a GPU.

## Review Focus

- A camera that never connects must not spin at 100% CPU or flood the log.
- A stream that stalls mid-frame must reconnect and reset motion state, not keep painting a frozen frame as live.
- A frame whose face is too small must still create a visit without being embedded.
- Two different unknown people within 60 s on one camera must not merge when their embeddings differ.
- The app must start and stay usable on a machine with no dlib models and no CUDA.
